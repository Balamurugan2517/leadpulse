LeadPulse AI — Troubleshooting Guide

Quick resolutions for common local development, database, discovery, and Vercel deployment issues.

1. Neon Database & Migration Issues

Symptom: `npm run db:push` fails saying `drizzle.config.json file does not exist`.

Resolution:

Ensure package.json uses --config=drizzle.config.ts and .env defines DATABASE_URL with ?sslmode=require.

npx drizzle-kit push --config=drizzle.config.ts

Symptom: Settings page shows "Offline / Mock Fallback" instead of Neon Connected.

Resolution:

Verify DATABASE_URL is set in .env (local) or Vercel Environment Variables (production), then click Test Connection Now in /dashboard/settings.

2. Discovery Studio & CRM Persistence

Symptom: Discovered leads appear in Discovery Studio, but are not yet in Lead Explorer.

Resolution:

Discovery Scan displays a staging preview first so you can review leads before saving. Click + Save to CRM on a card or Import All to CRM to write them to Neon DB.

Symptom: OpenStreetMap Overpass returns timeout or busy error.

Resolution:

Overpass has a 12-second timeout guard. If public Overpass servers are busy, LeadPulse automatically falls back to verified regional records and Startup India Open Data without crashing. Try narrowing the radius to 3 km or 5 km.

3. Vercel Deployment & Prototype Links

Symptom: Prototype preview links point to `localhost:3000` on Vercel.

Resolution:

Set NEXT_PUBLIC_APP_URL to your Vercel domain (e.g. https://leadpulse-pergeone.vercel.app). Dashboard preview buttons also automatically use relative /preview/... paths.

4. Audit Lab SSRF Blocked Error

Symptom: Audit Lab reports `SSRF Blocked` when auditing a URL.

Resolution:

By design, LeadPulse blocks private IPs (127.0.0.1, 192.168.x.x, 10.x.x.x) and non-HTTP/HTTPS schemes. Only test public business domains.
